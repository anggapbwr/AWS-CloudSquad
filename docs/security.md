# AWS CloudSquad — DevSecOps & Security Architecture

CloudSquad enforces **Secure by Default** architecture across code, container supply chain, and infrastructure.

---

## 1. Automated Security Toolchain

```text
SOURCE CODE ──► Semgrep (SAST)
             ──► Gitleaks (Secrets Detection)
             ──► Trivy (Container CVEs & Config)
             ──► Syft (SBOM Generation)
             ──► Cosign (Image Signing & Attestation)
             ──► Checkov (IaC Compliance)
             ──► BLOCKING POLICY GATE
```

---

## 2. Hard Security Gates

If any of the following conditions occur, the deployment is blocked immediately:

| Vulnerability Category | Tool | Blocking Threshold |
|---|---|---|
| **Critical CVEs** | Trivy | `CRITICAL > 0` |
| **High Severity CVEs** | Trivy | `HIGH > 0` |
| **Leaked Credentials** | Gitleaks | `findings_count > 0` |
| **Root Container Execution** | Dockerfile check | `USER root` or `UID 0` |
| **Public Database Subnets** | Checkov | Any RDS subnet mapped to an Internet Gateway |
| **Unencrypted Storage** | Checkov | Missing KMS encryption on S3, EBS, or RDS |

When a gate fails, the mission transitions to `FAILED` with status `DEPLOYMENT_BLOCKED` and the exact violation details are displayed in the cockpit.

---

## 3. Supply Chain Security (SBOM & Signing)
- **CycloneDX SBOM**: Generated by Syft, detailing every application package and version (`fastapi`, `pydantic`, `uvicorn`, `redis`, etc.).
- **Cosign Attestation**: Container digests are cryptographically signed using keyless OIDC identity verification.
