# AWS CloudSquad — Migration Plan & Codebase Assessment

This document maps the existing codebase against the new canonical specification, detailing what to **KEEP**, **REFACTOR**, **REPLACE**, **REMOVE**, and add as **NEW**.

---

## 1. Summary of Architectural Delta

| Dimension | Existing Implementation | Canonical Specification Target |
|---|---|---|
| **Architecture** | FastAPI monolithic script with in-memory dictionaries | Modular monolith + Temporal workers, PostgreSQL 16, Redis 7, S3/Storage |
| **Agent Roster** | 7 agents (`deployment.py` as agent 6) | 6 engineering agents (Deployment is a deterministic workflow stage) |
| **Workflow Engine** | Custom async loop in `services/orchestrator.py` | Durable Temporal workflow (`MissionWorkflow` with activities) |
| **Persistence** | In-memory `store.py` (`_missions: dict`) | PostgreSQL models with SQLAlchemy 2.0 + Alembic migrations |
| **Artifacts** | Minimal static strings returned in API route | Structured artifacts saved in object storage (S3/Local) and cataloged in DB |
| **Validation Gates** | Mock strings in agent returns | Real tool execution: `terraform fmt/validate/plan`, Checkov, Semgrep, Trivy, k6 |
| **AI Gateway** | None (simulated sleep in agents) | `LLMGateway` abstraction supporting AWS Bedrock, OpenAI, Anthropic, or deterministic fallback |
| **Frontend UI** | Static custom CSS canvas, mocked telemetry bar | React Flow topology canvas, Recharts telemetry, Zustand reactive state |

## 2. Granular Component Assessment

### A. KEEP (Compatible components to retain with minimal or zero adjustments)
- `frontend/package.json` — Core dependencies (`next`, `react`, `react-dom`, `tailwindcss`, `clsx`, `tailwind-merge`, `lucide-react`, `canvas-confetti`).
- `missions/ecommerce/spec.json` — High-concurrency e-commerce flash sale specification (canonical demo mission).
- `frontend/app/globals.css` — Global styling and dark-theme tokens.
- `frontend/components/Header.tsx` — Cockpit header visual design (to be connected to real status props).

### B. REFACTOR (Components with solid structure but requiring modernization)
- `backend/models/mission.py`
  - *Refactor into*: Canonical typed state machine (`MissionStatus`, `AgentStage`, `EventType`), typed requirement schemas, and SQLAlchemy database models + Pydantic schemas.
- `backend/services/event_bus.py`
  - *Refactor into*: Redis Pub/Sub backed event distributor with async fallback for local zero-dependency testing.
- `backend/api/missions.py`
  - *Refactor into*: Full REST CRUD endpoints backed by SQLAlchemy repository and Temporal workflow triggers.
- `backend/api/ws.py`
  - *Refactor into*: Robust WebSocket hub listening to Redis Pub/Sub channels per mission.
- `frontend/components/EngineerStation.tsx`
  - *Refactor into*: Exact 6-agent station (Architect, Database, Application, Infrastructure, DevSecOps, SRE) reflecting real live activity statuses.
- `frontend/components/EventTimeline.tsx`
  - *Refactor into*: Live WebSocket-driven event stream rendering canonical event types.
- `frontend/components/ArtifactModal.tsx`
  - *Refactor into*: Multi-tab code/syntax inspector supporting SQL, Terraform, JSON, and Markdown downloads.
- `docker-compose.yml`
  - *Refactor into*: Production compose setup running `frontend`, `backend`, `worker`, `postgres`, `redis`, `temporal`, and `temporal-ui`.

### C. REPLACE (Components being superseded by proper engineering implementations)
- `backend/models/store.py`
  - *Replace with*: SQLAlchemy 2.0 database repositories and session management.
- `backend/services/orchestrator.py`
  - *Replace with*: Temporal Workflow definitions and Activities for durable execution.
- `frontend/components/ArchitectureCanvas.tsx`
  - *Replace with*: Interactive **React Flow** canvas rendering dynamic topology nodes & edges generated by `ArchitectAgent`.
- `frontend/components/TelemetryBar.tsx`
  - *Replace with*: Real telemetry bar with **Recharts** charts showing RPS, P95 latency, error rates, and cost tracking.

### D. REMOVE (Obsolete or non-compliant elements)
- `backend/agents/deployment.py`
  - *Action*: REMOVE as an AI agent. Re-implement deployment strictly as a deterministic engineering stage within the workflow pipeline (`DeploymentService` / activity).

### E. NEW (New components to be built)
- `backend/config.py` — Centralized Pydantic settings with environment variable management.
- `backend/database/` — SQLAlchemy 2.0 database session, base, and models (`missions`, `workflow_runs`, `events`, `artifacts`, `deployments`, `security_scans`, `benchmarks`).
- `backend/schemas/` — Clean Pydantic request/response validation schemas.
- `backend/services/llm/` — `LLMGateway` abstraction supporting AWS Bedrock, OpenAI, Anthropic, and deterministic fallback.
- `backend/services/artifacts/` — Local & S3 artifact storage manager.
- `backend/services/deployment/` — Deterministic deployment service (Docker build, ECR, Terraform apply, ECS health verification).
- `backend/services/security/` — DevSecOps tool execution runners (Semgrep, Gitleaks, Trivy, Syft, Checkov).
- `backend/services/benchmarks/` — k6 performance testing runner and scenario generator.
- `backend/workflows/` — Temporal `MissionWorkflow` and activity implementations.
- `backend/workers/worker.py` — Temporal activity worker process.
- `terraform/modules/` — Standard modular Terraform modules (`vpc`, `alb`, `ecs`, `ecr`, `rds`, `iam`, `monitoring`).
- `tests/` — Comprehensive backend, agent, workflow, and API unit/integration tests.
- `.env.example` — Complete environment variable documentation.

## 3. Execution Phases (Aligned with Master Prompt #53)

```text
PHASE 1: Foundation (Docker Compose, Config, PostgreSQL, Redis, Backend & Frontend scaffolding)
PHASE 2: Mission Management & Persistence (SQLAlchemy models, CRUD API, Mission state machine)
PHASE 3: Event System & Real-Time Streaming (Redis Pub/Sub, WebSocket Hub, Frontend Timeline)
PHASE 4: Temporal Workflow Engine (Temporal setup, MissionWorkflow, Activities, Worker)
PHASE 5: Architect Agent (Structured architecture JSON, React Flow topology canvas)
PHASE 6: Database Agent (Schema SQL, migrations, database design artifacts)
PHASE 7: Application Agent (FastAPI app scaffold, Dockerfile, unit test verification)
PHASE 8: Infrastructure Agent & Validation Gates (Modular Terraform, fmt, validate, plan)
PHASE 9: DevSecOps Agent & Policy Gates (Semgrep, Gitleaks, Trivy, Syft, Checkov)
PHASE 10: AWS Deployment Stage (Deterministic ECR push, Terraform apply, ECS health check)
PHASE 11: Observability & Telemetry (CloudWatch metrics, Recharts frontend dashboard)
PHASE 12: Performance Testing (k6 baseline, load, stress, spike test runner)
PHASE 13: SRE Agent (SRE analysis, bottleneck identification, remediation proposals)
PHASE 14: Final Mission Report & Documentation (Consolidated engineering report & full docs)
```
